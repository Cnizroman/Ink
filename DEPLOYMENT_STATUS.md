## Исправление входа после развёртывания

  проверка CORS Chromium, без перехвата сетевых запросов. Проверяется реальный
  OPTIONS/preflight, старый клиент с Prefer, вход -> админка и разные ошибки.
- Во всех браузерных наборах удалён `--disable-web-security`.

## Исправление запуска OAuth после настройки GitHub

Проверка конфигурации Auth подтвердила: GitHub включён, Manual Linking включён,
адреса возврата правильные. Значения ключей не сохраняются в репозитории.

В клиенте не хватало `skip_http_redirect=true` на `/user/identities/authorize`.
Без него GoTrue перенаправлял `fetch` к провайдеру (302), вместо JSON с URL;
браузер получал сетевую ошибку, ошибочно подписанную как проблема настройки.
Запрос приведён к контракту `auth-js linkIdentity`: сначала JSON, затем
явная навигация браузера. Автоматические редиректы fetch запрещены, ответ
и HTTPS URL проверяются. Ошибки сети, формата ответа и конфигурации различаются.

`tests/browser-oauth.cjs` воспроизводил прежнее сообщение до исправления.
После исправления проверяет GoTrue-подобный 302/JSON контракт, HTTPS-навигацию
к локальному тестовому провайдеру, отмену, неправильный ответ и успешный
возврат в тот же аккаунт с удалением токенов из URL. Перехватов Playwright нет.
Внешнюю авторизацию GitHub и согласие владельца тест не выполняет.

## Уточнение: подготовка Telegram OAuth URL

Владелец подтвердил настройку провайдера, но реальный переход на Telegram
завершился `redirect_uri required`, хотя присланная ссылка содержит правильный
callback. Корневая причина пока не подтверждена. Добавлена защитная подготовка
ссылки: буквальные HTML-разделители нормализуются только для Telegram,
`redirect_to`/`skip_http_redirect` исключаются из исходящего URL, обязательные
параметры и точный callback проверяются до навигации. State/PKCE/nonce не
создаются и не подменяются. Возврат на сайт остаётся в серверном flow state.
GitHub/Discord не получают Telegram-преобразований. SW: `chernila-v16`.

Регрессии проверяют обычные/HTML-экранированные ссылки, отсутствие/пустые и
повторяющиеся обязательные поля, другой callback, сохранение state/PKCE,
браузерный возврат через тестовый Auth callback после удаления служебных
параметров. Это не подтверждение успешного подключения к настоящему Telegram:
после публикации нужна новая попытка владельца с сайта, не по старой ссылке.
