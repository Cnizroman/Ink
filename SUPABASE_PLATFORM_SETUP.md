# Общая база «Чернил»

> Для текущего проекта настройка базы, Storage, владельца и входа по юзернейму
> уже выполнена 2026-11-02. См. [DEPLOYMENT_STATUS.md](DEPLOYMENT_STATUS.md)
> — там указано, что осталось владельцу. Ниже — общая инструкция.

## Установка или обновление

1. Выполните **полный** `supabase-platform-schema.sql` в SQL Editor своего
   Supabase проекта. Его можно запускать повторно, данные книг и профилей
   не удаляются. На `#/setup` есть ссылка и копирование файла.
2. Зарегистрируйте/откройте свой настоящий аккаунт основателя и подтвердите
   его UUID через SQL Editor по [ADMIN_SETUP.md](ADMIN_SETUP.md).
3. Разверните функцию `supabase/functions/username-login/index.ts` по той же
   инструкции. До развёртывания входите по email в том же поле.
4. Для файлов профиля и подключения соцсетей настройте Storage/Auth
   по [SOCIAL_AND_MEDIA_SETUP.md](SOCIAL_AND_MEDIA_SETUP.md).
5. Перезагрузите сайт. Он сам определит готовые таблицы и подключит общую базу.

Профили создаются триггером регистрации. Старый триггер автоматического
подтверждения email **удаляется**: включите Confirm email в настройках Auth,
пользователь подтверждает почту по письму. Это важно для безопасной привязки
соцсетей. Права владельца назначаются отдельно через SQL Editor, не через
имя или метаданные.

## Что добавлено в обновлении v5

- Публичный Storage bucket `profile-media`: PNG/JPEG/WebP до 1 МБ, запись и
  удаление только в папке владельца; без ручного ввода URL.
- `profiles.customization.socialLinks`: проверяемые публичные ссылки на сети.
- Реальные OAuth-identities управляются **Supabase Auth**, не JSON профиля.
- Manual linking и провайдеры включаются отдельно в Dashboard; SQL не может
  создать OAuth-приложения у внешних сетей.
- Локальные версии мастерской не требуют новой таблицы и хранятся в браузере.

## Ранее добавлено в v4

- `profiles.customization` — оформление профиля.
- `work_groups` — состав и порядок циклов, с серверной проверкой принадлежности.
- `founder_work_settings` — настройки встроенных карточек без дублирования текстов.
- Защита `role`, `is_founder`, `username`, значков и владельца произведения.
- Возможность админу выдавать и отзывать значки у других авторов.
- Регистрация с юзернеймом `cnizroman` **сама по себе не даёт права админа**.

Конкурсы убраны из интерфейса и больше не создаются стартовыми данными.
Старые таблицы конкурсов не удаляются, чтобы не уничтожать существующие данные.
Старая система `reviews` / `reviews-admin.html` не изменяется.

Без SQL сайт продолжает работать локально: данные хранятся только в браузере,
аккаунт основателя `cnizroman / demo1234` существует только в этом режиме.
При подключении Supabase локальная сессия без настоящего токена сбрасывается.

Не кладите `service_role` или секретные ключи в публичные файлы сайта.
В `supabase-config.js` остаётся только публичная конфигурация.
