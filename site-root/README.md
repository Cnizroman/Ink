Содержимое этой папки предназначено для **корня отдельного репозитория `Cnizroman/Cnizroman.github.io`**, а не для переноса сайта Ink.

В файлах нет текстов книг, паролей, ключей расшифровки или конфигурации базы. Значения Google/Yandex — публичные токены подтверждения владения.

## Статус

Файлы подготовлены и проверены. Репозиторий `Cnizroman.github.io` создан владельцем, но пока пуст. Git push и прямая загрузка через GitHub Contents API из текущего подключения отклонены HTTP 403. Проверка установки `arena-ai-coding-agent` показывает доступ ко всем репозиториям, поэтому повторное переключение списка репозиториев не предлагается как подтверждённое решение. Корневой сайт **ещё не опубликован**.

Готовый архив с четырьмя файлами, без дополнительной папки:

## Если репозиторий ещё не создан

1. Откройте https://github.com/new под аккаунтом `Cnizroman`.
2. Имя репозитория: **`Cnizroman.github.io`**. Выберите **Public**.
3. Не добавляйте README, .gitignore или лицензию — оставьте репозиторий пустым. Нажмите **Create repository**.
4. Откройте https://github.com/settings/installations и найдите установленное приложение Arena. Нажмите **Configure**. Если выбрано **Only select repositories**, добавьте **Cnizroman.github.io**, сохранив доступ к **Ink**, и нажмите **Save**. Если уже выбрано **All repositories**, менять список не нужно.
5. Сообщите агенту, что репозиторий создан и доступ предоставлен. Агент сможет повторно проверить разрешения и продолжить публикацию. Если новый доступ не отразится в текущем подключении, потребуется обновить подключение GitHub в Arena.

Не присылайте токены доступа или пароли.

## Запасной ручной способ публикации

Если разрешение приложению выдать нельзя:

1. В новом репозитории выберите **uploading an existing file** (или **Add file → Upload files**).
2. Загрузите прямо в корень `index.html`, `robots.txt`, `yandex_f3798107dbb5423d.html` и `.nojekyll` из этой папки. Не загружайте папку `site-root` целиком и не загружайте ZIP как один файл.
3. Нажмите **Commit changes**.
4. Откройте **Settings → Pages**. В **Build and deployment → Source** выберите **Deploy from a branch**. В **Branch** выберите ветку с загруженными файлами и **/(root)**, затем **Save**.
5. Дождитесь успешной публикации. Проверьте адрес https://cnizroman.github.io/yandex_f3798107dbb5423d.html — он должен показывать `Verification: f3798107dbb5423d`, без 404 и редиректов.
6. Вернитесь в Яндекс Вебмастер, выберите ресурс `https://cnizroman.github.io`, вкладку **HTML-файл**, нажмите **Подтвердить**. Только успешный ответ Яндекса подтверждает права.

## Google

Ресурс Search Console остаётся **`https://cnizroman.github.io/Ink/`**, sitemap — **`https://cnizroman.github.io/Ink/sitemap.xml`**. Создание корневого сайта исправляет расположение файла Яндекса и размещает host-level robots.txt, но не доказывает причину или устранение ошибки Google «Не удалось обработать файл Sitemap».

Корневая страница не подменяет Ink: она содержит ссылку на него, canonical на `/Ink/` и `noindex,follow`, чтобы не создавать вторую индексируемую главную страницу.
