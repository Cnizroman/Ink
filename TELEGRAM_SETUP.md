# Настоящая привязка Telegram к профилю

Telegram подключается как **custom OIDC provider `custom:telegram`** через существующую систему Supabase Auth. Это привязка к уже вошедшему аккаунту, не создание второго профиля. GitHub и Discord менять не нужно.

Код клиента подготовлен. Реальная настройка Telegram/провайдера и вход настоящего пользователя агентом не выполнялись. Наличие Custom OAuth Providers в конкретном действующем проекте необходимо проверить в Dashboard. Коннектор Telegram в чате для подключения соцсети на сайте не нужен.

## 0. Проверить доступность пользовательского провайдера

1. Откройте проект: https://supabase.com/dashboard/project/ydxnhdbuxjrrpypkgkee.
2. Перейдите в **Authentication → Sign In / Providers** (или **Providers**).
3. Найдите **New Provider**, **Add Provider** или раздел **Custom OAuth Providers**.
4. В форме должна быть **Auto-discovery / OIDC**. Если этой возможности нет, остановитесь и сообщите, какие разделы доступны. Не используйте вместо этого случайный встроенный провайдер, например Keycloak, и не вставляйте секреты в код сайта.

## 1. Создать бота-представителя сайта

1. Откройте в Telegram официальный **@BotFather**: https://t.me/BotFather. Не используйте похожие имена/сторонних ботов.
2. Нажмите **Start / Запустить**, если чат ещё не запускался.
3. Отправьте `/newbot`.
4. На запрос имени введите `Чернила` (можно другое название).
5. На запрос username задайте свободное имя латиницей, заканчивающееся на `bot`, например `chernila_ink_login_bot`. Пример не гарантированно свободен; если занят, выберите другой.
6. После создания BotFather покажет **Bot API token**. Для выбранного способа подключения он не нужен. Не присылайте его в чат и не добавляйте в файлы сайта.

Запускать отдельный сервер, настраивать webhook, писать команды бота или добавлять его в группы для этой привязки не нужно. Создание бота само по себе не включает связь с сайтом.

## 2. Включить Telegram Web Login / OpenID Connect

Откройте мини-приложение управления ботами у @BotFather, выберите созданного бота и раздел **Login Widget**. В зависимости от версии интерфейса он может находиться в **Bot Settings → Web Login**. Используйте именно настройки входа на сайт.

Если предлагается **Switch to OpenID Connect Login**, выберите этот режим. Не настраивайте вместо него только старый `/setdomain`/legacy iframe widget: клиент сайта использует OIDC.

Зарегистрируйте:

- **Trusted Origins / Website origin** (если поле выделено отдельно):
  ```text
  https://cnizroman.github.io
  ```
- **Redirect URIs / Callback URL**:
  ```text
  https://ydxnhdbuxjrrpypkgkee.supabase.co/auth/v1/callback
  ```

Если вместо двух отдельных списков есть общий **Allowed URLs**, добавьте оба адреса отдельными записями. Сохраните изменения. Callback должен совпадать с read-only Callback URL формы Supabase; если панель показывает другой адрес, сначала сверьте настройки проекта, а не подбирайте адрес наугад.

Найдите здесь **Client ID** и **Client Secret**. Это OIDC-реквизиты, а **Client Secret — не Bot API token**. Секрет вводится только в Supabase Dashboard. Не присылайте его в чат и не показывайте на скриншотах. Если есть выбор алгоритма подписи, оставьте **RS256**; не отключайте проверки nonce.

## 3. Создать провайдера в Supabase

В **Authentication → Providers → New Provider** заполните:

| Поле | Значение |
| --- | --- |
| Provider Identifier | `telegram`, если `custom:` уже показан слева поля; итоговый идентификатор должен быть **`custom:telegram`** |
| Display Name / Name | `Telegram` |
| Configuration Method | **Auto-discovery (OIDC)** |
| Issuer URL | `https://oauth.telegram.org` |
| Client ID | Client ID из настроек Web Login @BotFather |
| Client Secret | OIDC Client Secret оттуда же, не Bot API token |
| Scopes | `openid, profile`, если поле принимает список через запятую |
| Allow users without email | **Включить** (`email_optional=true`) |

Email-optional нужен, потому что Telegram не передаёт email в этом наборе claims. Это настройка только этого провайдера, не указание менять глобальное подтверждение почты или email своего аккаунта.

Если интерфейс предлагает отдельное поле **Discovery URL**, значение:

```text
https://oauth.telegram.org/.well-known/openid-configuration
```

Не вставляйте полный discovery URL в **Issuer URL**. При auto-discovery отдельные Authorization/Token/UserInfo endpoints вручную не нужны.

PKCE оставьте включённым. Не включайте Skip nonce check. Не добавляйте scopes `email`, `phone` или `telegram:bot_access`: сайту нужны только идентификатор и публичные данные профиля. Нажмите **Create and enable provider** / **Save** и убедитесь, что провайдер включён. Разрешение Manual Linking, которое уже используется GitHub/Discord, оставьте без изменений.

Client Secret остаётся на сервере Supabase. Для этого подключения не требуется запускать новый SQL, развёртывать Edge Function или менять публичный `supabase-config.js`.

## 4. Подключить аккаунт на «Чернилах»

1. Откройте https://cnizroman.github.io/Ink/ и войдите в **свой существующий аккаунт**.
2. Откройте редактор профиля → **Подключённые аккаунты**.
3. Если нужно, обновите страницу через Ctrl+Shift+R и нажмите **Проверить подключения**.
4. В карточке Telegram нажмите **Проверить и подключить**.
5. Пройдите подтверждение на официальной странице Telegram и дождитесь возврата на сайт.
6. Карточка должна показать **Подключён**. После обновления страницы статус должен сохраниться; аккаунт «Чернил» не должен измениться.

До настоящего ответа авторизации карточка намеренно показывает **Проверяется при подключении**, а не «Настроено»: публичный `/auth/v1/settings` Supabase перечисляет встроенных провайдеров, но не custom OIDC. Пробовать привязку можно, а объявлять провайдера настроенным по отсутствующим данным нельзя.

У пользователя может не быть Telegram username. Подтверждённая привязка всё равно возможна, но автоматически создать публичную ссылку `t.me/username` в этом случае нельзя. Числовой Telegram ID за публичный username не выдаётся.

## 5. Публичная ссылка — отдельно

После успешной привязки, если Telegram передал username, появится **Добавить ссылку в профиль**. Нажмите её и **Сохранить профиль**, только если хотите показывать контакт читателям. Вручную добавленная публичная ссылка не становится подтверждённой привязкой.

**Отключить** удаляет identity Telegram через Supabase Auth; публичная ссылка при этом не удаляется автоматически. Отключение последнего identity не разрешается. GitHub и Discord сохраняются.

## Если возникла ошибка

- **Нужна настройка `custom:telegram`**: проверьте точный идентификатор, включение провайдера и доступность Custom OAuth Providers в проекте.
- **Недопустимый redirect URI**: проверьте точный callback, HTTPS, отсутствие лишнего `/` и сохранение настроек у BotFather.
- **`redirect_uri required` на странице Telegram**: закройте старую страницу авторизации, откройте сайт заново, обновите через Ctrl+Shift+R и начните новую привязку. Клиент проверяет обязательные параметры и callback до перехода, исправляет буквальные HTML-разделители `&amp;` и убирает служебные параметры Supabase из ссылки Telegram. Если ошибка повторится, сообщите точный текст и домен страницы, но не отправляйте полный OAuth URL со state/nonce. Наличие callback в ссылке само по себе не доказывает причину ошибки; менять правильный callback наугад не нужно.
- **`invalid_client`**: проверьте Client ID и именно OIDC Client Secret, не токен бота.
- **Ошибка email**: проверьте **Allow users without email** и отсутствие scope `email`.
- **Нет `Подключён` после возврата**: пришлите текст ошибки без URL с токенами, секретов и данных сессии. Клиент не принимает ответ от другого аккаунта, неправильный/просроченный nonce и отсутствие identity `custom:telegram`.

## Источники и проверка

- Telegram: https://core.telegram.org/bots/telegram-login.
- Supabase: https://supabase.com/docs/guides/auth/custom-oauth-providers.
- Контракт публичного `/settings` и custom provider: исходники `supabase/auth`, `internal/api/settings.go`, `external.go`, `identity.go`.
- Названия полей Dashboard: `supabase/supabase`, `apps/studio/components/interfaces/Auth/CustomAuthProviders/CreateOrUpdateCustomProviderSheet.tsx`.

Модульные тесты проверяют `custom:telegram`, минимальные scopes, точный identity при возврате, запрет смены аккаунта, ошибку отсутствующего провайдера и безопасное построение публичной ссылки. `tests/browser-oauth.cjs` проверяет запуск/отказ/подключение/публикацию ссылки/отключение через локальные HTTP/TLS-серверы с включённой браузерной проверкой CORS, без перехвата запросов. Дополнительно проверяются HTML-экранированная ссылка, отсутствие callback, удаление служебных параметров Auth и сохранение state/PKCE при возврате через callback тестового сервера. Это не проверка настоящего Telegram или конфигурации живого проекта.
