# «Где нас нет»: серверная защита

## Владельцу: один обязательный шаг после публикации

Старые коды были извлекаемы из публичного JavaScript. Они **не перенесены** на сервер и больше не открывают новую читалку. Пока владелец не задаст новый пароль, доступ закрыт для всех читателей.

1. Откройте https://cnizroman.github.io/Ink/ и войдите в свой настоящий аккаунт `cnizroman` (не локальный демонстрационный режим).
2. Откройте **Мастерская → Мои произведения → «Где нас нет» → Редактировать**. Прямая ссылка: https://cnizroman.github.io/Ink/index.html#/studio/work/gde-nas-net
3. Разверните **«Доступ к „Где нас нет“ · серверная защита»**.
4. Введите новый отдельный пароль два раза и нажмите **«Заменить старые пароли»**. Не используйте пароль аккаунта или прежние коды. Минимум 8 символов, максимум 72 байта UTF-8.
5. Откройте https://cnizroman.github.io/Ink/book3.html в приватном окне. Неверный пароль не должен открывать текст; новый должен открыть историю и проигрыватель. После обновления пароль потребуется снова.
6. Сообщите новый пароль тем, кому разрешаете читать. Не добавляйте его в исходники, комментарии GitHub или чат.

Никакой SQL вручную для первого запуска выполнять не нужно: миграция и закрытая запись ключа уже настроены в существующем проекте Supabase.

## Что защищено

- В `book3.html` осталась только форма входа. Ни `<main>`, ни шаблона с текстом, ни интерфейса чтения до разблокировки нет.
- Текст актуальной авторской версии и голосовое находятся в `assets/protected/` только в виде AES-256-GCM шифротекста. У каждого компонента свой случайный IV и отдельные аутентифицируемые данные.
- Ключ не записан в Git, HTML или JS. Его выдаёт POST RPC `unlock_legacy_book` после серверной bcrypt-проверки. Клиент проверяет SHA-256 всего пакета перед расшифровкой.
- `ink_private.legacy_book_access` не доступна через обычное чтение REST. RLS включена, у `anon`/`authenticated` нет доступа к схеме/таблицам. Поменять пароль может только UUID владельца, а не любой другой администратор.
- Пустой, неверный, слишком длинный пароль, отсутствие настройки, сбой сети и повреждённый пакет закрывают доступ, а не показывают запасной текст.
- Общий лимит — 60 проверок за 5 минут; успешные проверки тоже учитываются. Это защита от перебора, но атакующий может временно исчерпать общий бюджет. Владелец может сбросить его сохранением пароля. Для большой аудитории нужен отдельный шлюз с надёжным per-IP лимитированием.
- `book3-final-voice.html` перенаправляет на защищённый вход; прежний открытый MP3 удалён из текущей версии сайта. Аудио расшифровывается в памяти после доступа и первого нажатия Play.
- Пароль, ключ и расшифрованный текст не сохраняются в localStorage/sessionStorage/IndexedDB/Cache API. Чтение требует сети; возврат из bfcache приводит к перезагрузке входа. При уходе со страницы текст убирается и blob аудио освобождается.
- Service worker `chernila-v23` удаляет старые кеши и никогда не подставляет старый HTML/MP3 этой истории в качестве офлайн-копии.

## Пределы защиты

Это контроль доступа, не DRM. Читатель после разрешённого открытия может скопировать текст, сохранить аудио или поделиться полученным ключом. Смена пароля не отзывает уже выданные копии/ключи текущего пакета. При каждой новой упаковке генерируется новый ключ.

Старый текст, аудио и прежние коды уже были опубликованы в истории публичного Git-репозитория. Новая защита **не удаляет прошлые коммиты, скачанные копии, старые вкладки и чужие кеши**. Историю Git не переписывали и force-push не применяли. Очистка старого браузерного кеша происходит после получения нового service worker онлайн, не задним числом у отключённого от сети устройства.

Последняя авторская правка `book3.html` сохранена при упаковке. Старый альтернативный шаблон в этой правке уже отсутствовал; его устаревший, неанонимизированный текст из резервных файлов не возвращался.

## Разработчику: дальнейшее редактирование авторского текста

Не вставляйте текст обратно в публичный HTML. Держите авторские исходники и ключи вне Git. Папка `.cache/` игнорируется Git, но её нужно считать временной: храните собственную приватную резервную копию.

Для восстановления редактируемой копии при наличии закрытого `.cache/book3-secret.json`:

```sh
node scripts/protect-legacy-book.cjs unpack
```

Команда проверит целостность, расшифрует текущий пакет и создаст только игнорируемые `.cache/book3-author.html` и `.cache/book3-author.mp3`. Для просмотра не открывайте доступ к `.cache/` через публичный dev-server.

Если локальная закрытая метаинформация утрачена, её может получить владелец базы в **Supabase → SQL Editor**, но не обычный посетитель сайта:

```sql
select asset_id as "assetId", content_key as "key"
from ink_private.legacy_book_access where slug = 'book3';
```

Сохраните одну запись в приватный JSON-файл формата `{"assetId":"…","key":"…"}` вне Git и передайте его путь третьим аргументом `unpack`. Не публикуйте результат SQL и не добавляйте его в миграции.

После редактирования исходника:

```sh
node scripts/protect-legacy-book.cjs .cache/book3-author.html .cache/book3-author.mp3
```

Появятся новый публичный **зашифрованный** пакет с SHA-256 в имени и новая закрытая `.cache/book3-secret.json`. Новую метаинформацию никому не показывайте.

Порядок обновления без рассинхронизации:

1. Сначала опубликуйте новый зашифрованный пакет, оставив предыдущий файл доступным.
2. Дождитесь успешной сборки Pages.
3. Обновите **только** `asset_id`, `content_key`, `updated_at` закрытой записи `slug='book3'` значениями новой приватной метаинформации через доверенное подключение владельца. Не сбрасывайте `password_hash`/`password_ready`: действующий новый пароль должен сохраниться.
4. Проверьте открытие и аудио. Только потом удаляйте старый пакет, если он больше не нужен. Из-за сохранённых старых копий это не отзывает прежний доступ.

Миграция схемы: `supabase/migrations/20261105000600_legacy_book_access.sql`. Секретная начальная запись намеренно не включена в миграцию: в ней нет ни ключа, ни настоящих паролей, ни текста произведения.

## Проверки

- `npm test`: включая AES-GCM, отсутствие текста в воротах и регрессии повторных сцен.
- `npm run test:sql`: включая RLS, владельца, отключённый первичный доступ, смену пароля, отказ прежних кодов и ограничение попыток.
- `node tests/browser-legacy-book.cjs`: реальный Chromium/WebCrypto; удаление DOM-ворот, неверный пароль, отсутствие первичной настройки, обрыв сети, расшифровка текста/аудио, повторный вход, перенаправление старой копии, форма владельца и реальный service worker с устаревшим кешем. Используются только искусственные тексты и пароли, не производственные секреты.
