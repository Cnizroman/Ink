# Файлы профиля и подключение соцсетей (v5)

## 1. Изображения с устройства

Повторно выполните **полный** `supabase-platform-schema.sql` в SQL Editor.
В настоящем Supabase он создаёт/настраивает публичный Storage bucket
`profile-media` и политики доступа:

- чтение изображений публичное: это аватары и баннеры, не приватные файлы;
- загрузка/удаление — только внутри папки текущего `auth.uid()`;
- разрешены PNG, JPEG, WebP, обработанный файл не больше 1 МБ;
- имена объектов уникальные, без перезаписи чужих файлов.

На странице профиля выбирается **файл**, а не URL. Пользователь настраивает
кадр: горизонталь, вертикаль и масштаб. Исходник до 12 МБ / 24 Мп; перед
загрузкой изображение декодируется, кадрируется и заново кодируется браузером.
SVG/HTML не принимаются. Аватар сохраняется 512×512, баннер — 1600×500.
Ссылки на Storage генерируются самим сайтом и пользователем не вводятся.

При ошибке сохранения новые загруженные файлы удаляются, старое изображение
профиля остаётся. При успешной замене старый объект удаляется после обновления
профиля. Если вкладка аварийно закрылась во время загрузки, может остаться
неиспользуемый файл — его можно удалить в Storage. Миграция не стирает старые
изображения вслепую.

В **локальном режиме** кадрированные изображения сохраняются в браузере,
не на сервере и не для всех посетителей. При нехватке места показывается
ошибка, а не ложное сообщение об успехе. При переключении на общую базу
локальные изображения нужно загрузить заново в настоящий аккаунт.

## 2. Выбор сети и настоящая OAuth-привязка

В списке профиля есть два честно обозначенных варианта:

| Сеть | Публичная ссылка | OAuth-привязка к текущему аккаунту |
| --- | --- | --- |
| GitHub | Да | Да, после настройки провайдера |
| Discord | Да (числовой ID) | Да, после настройки провайдера |
| Twitch | Да | Да, после настройки провайдера |
| X / Twitter | Да | Да, после настройки провайдера |
| Facebook | Да | Да, после настройки провайдера |
| LinkedIn | Да | Да, провайдер `linkedin_oidc` |
| Telegram, ВКонтакте, YouTube, Instagram | Да | В этой версии нет |

Пользователь выбирает сеть и указывает короткое имя или адрес профиля.
Сайт строит и проверяет ссылку на домен выбранной сети. Публичная ссылка
**не выдаётся за доказательство владения аккаунтом**. Подтверждённый статус
появляется только из реального ответа Supabase Auth `/user.identities`.
OAuth-подключение не публикует произвольные приватные сведения и не выдаёт
права администратора. Добавление публичной кнопки профиля — отдельное действие.

### Настройка владельцем (один раз для каждой нужной сети)

1. В Supabase Auth включите **Confirm email**. Старый триггер автоматического
   подтверждения произвольной почты удалён обновлением. Проверьте существующие
   аккаунты, которым старая версия могла подтвердить почту автоматически.
2. Зарегистрируйте OAuth-приложение у нужного провайдера. В его **Callback URL**
   укажите адрес, который показывает Supabase: `https://<project-ref>.supabase.co/auth/v1/callback`.
3. В настройках **Auth → Providers** включите нужный провайдер и внесите его
   Client ID / Client Secret. Секреты остаются в Supabase, не в репозитории.
   У провайдера могут быть дополнительные требования к публикации приложения.
4. В настройках Auth разрешите **Manual Identity Linking** / **Allow manual
   linking**. Сайт использует именно привязку к текущему аккаунту, а не
   незаметный вход в новый профиль через другую сеть.
5. В **Auth → URL Configuration** задайте Site URL сайта и добавьте разрешённый
   redirect для возврата. Для текущего GitHub Pages:
   `https://cnizroman.github.io/Ink/**`.
   Для своего домена используйте свой точный хост и путь, не все домены подряд.
6. Подтвердите email аккаунта, войдите на сайт и нажмите в профиле
   **«Подключить [сеть]»**. Откроется официальная авторизация. Пароль соцсети
   в интерфейс «Чернил» не вводится.

При возврате проверяются одноразовый nonce, срок действия, тот же User UID и
наличие соответствующей identity. Токены сразу удаляются из адресной строки.
Сессия другого пользователя не подменяет текущую. Можно отключить привязку,
но не последний способ входа. Публичная ссылка при отключении не удаляется
молча — она управляется отдельно.

Без настройки провайдера кнопка покажет ошибку, а не вымышленное «подключено».
В локальном режиме доступно сохранение ссылок, OAuth недоступен.
Не все сети поддерживаются как провайдеры в этой версии: кнопки для Telegram,
VK, YouTube и Instagram намеренно не имитируют авторизацию.

## Проверки

`npm test` — формат, кадрирование, ограничения файлов, соцссылки, сессии,
nonce/UID, безопасный текст и локальные данные.

`npm run test:sql` — полная схема дважды, в том числе Storage RLS с запретом
загрузки/удаления в чужой папке.

При запущенном локальном сервере `npm run test:browser` проверяет выбор файлов,
предпросмотр, кадрирование, сохранение/ошибки, мастерскую и OAuth-возврат с
подставным тестовым Supabase. **Внешние реальные аккаунты тесты не подключают.**
